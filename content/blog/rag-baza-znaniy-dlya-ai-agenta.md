«Нам нужен RAG» звучит солидно. На практике половина пилотов живёт на **аккуратном FAQ + прайсе + правилах**, без векторной базы. RAG подключают, когда документов много и они часто меняются.

## Что такое RAG простыми словами

**RAG** (retrieval-augmented generation) — агент сначала **ищет** фрагмент в вашей базе, потом отвечает. Меньше выдумок по прайсу и условиям, если база живая.

Без поиска модель опирается на общий «опыт» и галлюцинирует цифры.

## Минимум на пилот (без тяжёлого RAG)

Соберите один документ (или папку) с:

1. **FAQ** — 20–40 реальных вопросов клиентов  
2. **Прайс / пакеты** — актуальные на дату  
3. **Границы** — чего агент не обещает (скидки, сроки, юридическое)  
4. **Эскалация** — когда звать человека  
5. **Тон** — коротко: вы / ты, формальность  

Этого хватает для квалификации лидов и первой линии. Контур записи — всё равно [CRM](/blog/ai-agent-i-crm-minimalnye-integracii).

## Когда RAG уже нужен

- База > 50–100 страниц (регламенты, каталоги, договоры)  
- Документы обновляются еженедельно  
- Несколько продуктов / юрлиц с разными условиями  
- Требование: «отвечать только цитатой из базы»  

Тогда: нарезка чанков, обновление индекса, тест на контрольных вопросах.

## Типичные ошибки базы знаний

| Ошибка | Результат |
|--------|-----------|
| Устаревший прайс | Агент обещает не то |
| Маркетинговые «вода»-тексты | Размазанные ответы |
| Нет раздела «запрещено» | Скидки и юр. обещания |
| PDF на 200 стр. без структуры | Плохой поиск / шум |

## Чек-лист готовности к пилоту

- [ ] FAQ согласован с РОПом / поддержкой  
- [ ] Прайс с датой актуальности  
- [ ] Список запретов  
- [ ] 10 тестовых вопросов с эталонными ответами  
- [ ] Владелец, кто обновляет базу раз в 2 недели  

## Связь с безопасностью

Персональные данные клиентов в базе знаний — зона 152-ФЗ. Не кладите туда выгрузки CRM «на всякий случай». Разбор — [on-premise и 152-ФЗ](/blog/ai-agent-152-fz-on-premise).
