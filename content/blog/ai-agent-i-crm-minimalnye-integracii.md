«Подключим ChatGPT к CRM» — так начинается половина созвонов. Через месяц выясняется: лиды дублируются, агент пишет не в ту воронку, менеджеры не доверяют ответам, а в логах пусто.

AI-агент в production — это не промпт. Это **контур данных**: откуда берёт заявку, куда пишет результат, кто видит ошибку. Ниже — минимум интеграций, без которого проект не взлетает. Это то, что продают dodigital.ru, MBK-Agent и NeoGraph — только короче и для владельца, не для разработчика.

## Зачем CRM агенту вообще

CRM — единственное место, где бизнес помнит клиента между касаниями. Без неё агент:

- отвечает «в вакууме», не видя историю сделки;
- не может передать лид менеджеру с контекстом;
- не оставляет след для РОПа и аналитики.

**Минимальная цель интеграции:** каждое действие агента = запись в CRM (контакт, сделка, задача, комментарий).

## Контур №1: входящий лид

| Элемент | Что должно быть |
|---------|-----------------|
| Источник | Форма сайта, Telegram, почта, реклама — **одна** точка входа или сводка в CRM |
| Триггер | Новая заявка / новое сообщение → запуск агента |
| Поля | Имя, телефон, канал, UTM, текст обращения |
| Дедупликация | Проверка «этот телефон уже в базе» |

Без дедупликации через 2 недели в CRM бардак. Конкуренты в SPb (USS-SPb) делают акцент на «интеграция в реальные процессы» — это и есть такой контур.

## Контур №2: квалификация и маршрутизация

Агент не «продаёт». Он **классифицирует** и **маршрутизирует**:

1. Задаёт уточняющие вопросы по регламенту (бюджет, срок, ЛПР).
2. Ставит статус: горячий / тёплый / отказ / спам.
3. Назначает ответственного или очередь.
4. Создаёт задачу менеджеру с кратким резюме.

**Минимум в CRM:** смена стадии воронки + комментарий + задача с дедлайном.

## Контур №3: права и безопасность

Типичные системы: amoCRM, Битrix24, HubSpot, SberCRM, 1С через API.

| Вопрос | Почему важен |
|--------|--------------|
| Под каким пользователем работает агент? | Чтобы видеть, кто «написал» в карточке |
| Какие поля можно менять? | Агент не должен трогать сумму сделки без правил |
| Где хранятся персональные данные? | 152-ФЗ: логи, доступ, on-premise при необходимости |
| Есть ли sandbox? | Тест на копии воронки до production |

Екатеринбургский рынок (aiagent0.ru) часто требует security-аудит — закладывайте это в ТЗ, даже если проект удалённый.

## Контур №4: логирование и эскалация

**Лог** — не опция. Минимум в логе:

- id заявки / сделки;
- что агент получил на вход;
- какое решение принял;
- что записал в CRM;
- версия промпта / правил.

**Эскалация на человека** — когда:

- клиент просит скидку / нестандарт;
- негатив или юридический вопрос;
- confidence ниже порога;
- сумма сделки выше лимита.

MBK-Agent для застройщиков продаёт «агент держит первую линию, РОП видит воронку» — это невозможно без логов и эскалации.

## Контур №5: обратная связь в канал

Клиент написал в Telegram — ответ тоже в Telegram (или SMS/email по регламенту). CRM — система учёта, канал — место диалога.

Цикл: **канал ↔ агент ↔ CRM**. Разрыв любого звена = «агент есть, пользы нет».

## amoCRM vs Битrix24: что учесть

| | amoCRM | Битrix24 |
|---|--------|----------|
| API | зрелый REST | REST + вебхуки |
| Типичный пилот | входящие лиды, статусы | лиды + задачи + чаты |
| Риск | дубли контактов | права и роли сложнее |

Не нужно «интегрировать всё». На пилоте достаточно: **создать/обновить сделку + задача + комментарий**.

## Чек-лист перед стартом интеграции

- [ ] Есть API-ключ или OAuth с ограниченными правами  
- [ ] Описана воронка: стадии, кто ответственный  
- [ ] Единый источник заявок (или правило слияния)  
- [ ] Регламент эскалации (когда зовём человека)  
- [ ] Логи хранятся минимум 30 дней  
- [ ] Тестовая воронка / тег «pilot» для отделения от боевых сделок  

## Сколько это стоит в проекте

Интеграция — часть пилота, не отдельная «магия». В типичном B2B-проекте (200–700 тыс. ₽) на CRM уходит заметная доля первого этапа, потому что без неё агент не production.

Сравнение с «ботом за 30 тыс.» — у dodigital.ru честно пишут: реальный агент от 150 тыс. и 4–6 недель. Дешёвый вариант без CRM — демо.
